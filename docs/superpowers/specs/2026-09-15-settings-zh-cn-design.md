# 设置页简体中文本地化设计

## 背景

基础汉化已经为 Web 客户端建立了简体中文语言偏好、类型安全的消息词典、语言切换，以及连接状态、导航、差异面板和输入区等主要界面的翻译。本轮在此基础上补齐设置界面的主要可见区域，并保持英文界面及既有设置行为不变。

实现分支以 `upstream/main` 的 `6ecc15fa25c808922a58f07377add25b55d9ac90` 为基础，包含从 `edd8003b7f4053d605e646a2f6d0074b7901330d` 移植的基础汉化。原 `feat/web-zh-cn` 分支和现有拉取请求保持不变。

## 目标与成功标准

本轮完成以下结果：

- 简体中文界面下，设置页顶栏、面包屑、环境与项目作用域菜单使用中文。
- 简体中文界面下，常规设置页和外观设置页的全部应用自有文案使用中文，包括标题、说明、选项、状态、弹窗、Toast、错误提示和无障碍标签。
- 设置搜索结果标题在简体中文界面下使用中文。
- 设置搜索同时接受中文和原有英文标题、关键词，并命中同一稳定设置项。
- 英文界面文案和搜索行为保持现状。
- 路由、稳定 ID、作用域判断、结果排序、设置值、持久化和交互行为不变。
- 桌面和窄屏布局没有新增裁切、溢出或垂直位移。

## 范围

### 包含

- 设置页公共顶栏和面包屑。
- 环境、项目作用域选择器及设置搜索引发的作用域提示。
- 常规设置页及从该页面直接打开的弹窗和提示，包括其直接子组件在常规分类中的可见文案。
- 外观设置页及从该页面直接打开的主题导入、主题搜索、主题编辑、主题删除等弹窗和提示。
- 设置侧栏搜索的全部目录项标题、中文搜索关键词和结果分类副标题。
- 以上区域中的无障碍名称、Tooltip、空状态、加载状态、失败提示和恢复默认值提示。

### 不包含

以下分类的正文不在本轮完整汉化范围内：

- 项目
- 快捷键
- 截屏
- 提供商
- 集成
- 源代码管理
- 连接
- 归档

这些分类仍会在侧栏分类名、面包屑和搜索结果中显示中文，但其页面正文不做系统性翻译。全应用顶栏、桌面窗口菜单、移动端及服务端文案也不在本轮范围内。

### 保留原文

以下内容不翻译：

- `GitHub`、`WSL`、`T3 Connect` 等产品名和协议名。
- 模型名、提供商名、主题名和第三方扩展名。
- 路径、文件名、命令、快捷键和配置键。
- 项目名、环境名、版本号、URL 及用户输入。
- 来自浏览器、操作系统、远端服务或异常对象的原始错误详情。

应用自有的错误标题和处理建议需要翻译；动态错误详情通过插值原样保留。

## 设计决策

### 1. 延续现有类型安全消息词典

`apps/web/src/i18n/messages.ts` 继续是唯一消息词典入口。英文词典仍是键集合的来源：

- `MessageKey` 继续由 `keyof typeof EN_MESSAGES` 推导。
- 简体中文词典继续使用 `satisfies Record<MessageKey, string>`。
- 词典测试继续比较英文和简体中文键集合，阻止缺失或多余键进入提交。
- 动态内容继续通过现有 `{name}` 插值传入，不在组件内拼接翻译后的句子。

新增消息按职责划分到以下命名空间：

- `settings.header.*`：设置顶栏、面包屑和恢复设备默认值。
- `settings.scope.*`：环境与项目作用域菜单、不可用状态和作用域提示。
- `settings.general.*`：常规页及其弹窗、状态、操作和无障碍文案。
- `settings.appearance.*`：外观页、主题库、主题导入与编辑流程。
- `settings.search.item.*`：设置搜索条目的标题和本地化关键词。

同一设置枚举的持久化值保持不变。界面显示通过 `Record<枚举类型, MessageKey>` 映射后调用 `t(...)`，不把中文写入状态或存储。

### 2. 设置顶栏与作用域

`SettingsBreadcrumb.tsx` 和 `routes/settings.tsx` 接入 `useI18n()`：

- 面包屑的“设置”、当前分类、诊断和开源许可证名称使用消息键。
- 面包屑的 `aria-label` 使用消息键。
- 环境和项目作用域触发器、全部环境、全部项目、不可用状态和离线状态使用消息键。
- 环境名、项目名和工作区路径仍直接显示原始数据。
- “恢复设备默认值”按钮只替换文案，不改变禁用条件、事件处理或尺寸。

设置搜索落到不兼容作用域时，`SettingsScopeBoundary` 和 `SettingsScopeNotice` 使用翻译后的设置标题与提示模板。选择目标的行为、候选集合和 URL 更新逻辑保持不变。

### 3. 常规和外观页面

`SettingsPanels.tsx` 中常规与外观分支调用 `useI18n()`，把现有硬编码显示文本替换为消息键。直接子组件按实际渲染范围处理：

- 常规页包括通知设置，以及 `ProjectDefaultsSettings` 在常规分类中渲染的默认模型、权限和工作区内容。
- 外观页包括主题库、主题预览操作、主题导入、Open VSX 主题搜索、主题编辑器、颜色选择器、字体预览和面板动画预览中的应用自有文案。

共享组件若同时被排除范围内的页面使用，采用调用方传入的可选翻译文案或只在目标分类分支调用翻译，默认英文行为保持不变。不得为了复用而让其他设置分类出现零散、无法验收的正文汉化。

所有修改只替换文本来源。以下内容保持不变：

- DOM 层级和元素类型。
- `className`、控件宽度、网格、滚动和折叠结构。
- 设置状态模型、默认值和持久化值。
- 条件渲染、事件处理、异步调用和错误分支。
- 主题文件格式、导入校验和第三方搜索请求。

### 4. 双语设置搜索

`settingsSearch.ts` 继续保存目录项的稳定结构和英文搜索资料。每个搜索项保留：

- `id`、`to`、`targetId`、`scope` 和可用性标记。
- 当前英文 `title`，作为兼容来源和英文检索字段。
- 当前英文 `searchTerms`，原样保留。

每个目录项新增类型安全的 `titleKey` 和 `localizedSearchTermsKey`。对应词典值提供：

- 英文显示标题和英文别名。
- 简体中文显示标题和常用中文搜索词。
- 需要保留的品牌、命令和协议关键词。

搜索界面把当前 `t` 函数传入目录搜索。每项参与匹配的字段为：

1. 原英文标题。
2. 原英文分类名。
3. 原英文关键词。
4. 当前语言标题。
5. 当前语言分类名。
6. 当前语言关键词。

标题排名对英文标题和当前语言标题分别计算，并取最高等级；非标题字段仍使用现有字段命中等级。最终仍按“排名降序、目录原始索引升序”排列。因此英文查询的结果与顺序不变，中文精确标题或前缀可以获得与英文标题相同的排名，平分时仍保持目录顺序。

`searchableSetting`、搜索结果标题和作用域提示通过统一的标题解析函数取得当前语言标题。未传翻译函数的纯逻辑调用继续使用英文标题，以保持现有测试和非 React 调用兼容。

### 5. 数据流

语言偏好仍由现有 `I18nProvider` 解析。数据流为：

1. `I18nProvider` 根据设备语言偏好提供 `language` 和 `t`。
2. 设置顶栏、常规页、外观页和搜索侧栏在渲染时读取 `t`。
3. 枚举值先映射为 `MessageKey`，再解析为显示文本。
4. 搜索函数同时读取目录中的英文静态字段和通过 `t` 得到的当前语言字段。
5. 搜索结果继续返回原目录项；导航仍使用原 `id`、路由和作用域元数据。
6. 动态名称与错误详情只作为插值值进入已翻译模板，不进入词典键或稳定目录数据。

切换语言只触发正常的 React 重渲染，不迁移或重写任何设置值。

## 错误处理

本轮不新增错误类型或重试策略。现有错误分支保持原样，只调整显示方式：

- 应用定义的错误标题、操作建议和回退说明由词典提供。
- 外部错误详情原样插入翻译模板，不尝试解析或翻译。
- 主题导入、主题保存和外部主题搜索仍使用当前成功、失败和禁用条件。
- 缺失词典键在 TypeScript 和词典完整性测试中失败，不添加运行时静默回退。

## 测试策略

实现遵循测试先行。每个行为先增加能正确失败的测试，再做最小实现。

### 自动化测试

1. 消息词典测试
   - 英文和简体中文键集合完全一致。
   - 顶栏、作用域、常规、外观和搜索代表性键返回预期中文。
   - 动态项目名、环境名和错误详情插值后保持原文。

2. 设置搜索测试
   - 中文标题和中文关键词能命中目标项。
   - 原英文标题和英文关键词仍命中同一 `id`。
   - 英文查询的结果顺序保持现有断言。
   - 路由、`targetId`、作用域和可用性过滤断言保持不变。
   - 搜索结果显示标题随语言变化，品牌名保持原文。

3. 顶栏和作用域组件测试
   - 简体中文下输出中文面包屑、菜单标签、离线状态和恢复默认值文案。
   - 动态环境名和项目名不改变。
   - 英文下保持当前文案。

4. 常规和外观代表性组件测试
   - 简体中文下分别覆盖页面标题、说明、枚举选项、弹窗或 Toast、无障碍标签。
   - 英文下保留代表性现有文案。
   - 现有设置逻辑测试继续通过。

定向测试从 `apps/web` 执行，并显式使用隔离工作树的 `node_modules/.bin/vp.cmd`，避免解析到其他工作树的测试运行器。最终测试集合包含现有 i18n、设置搜索和设置布局测试，以及本轮新增的面包屑、常规和外观本地化测试。

### 静态验证

从仓库根目录执行：

- Web 定向类型检查：`node_modules/.bin/vp.cmd run --filter @t3tools/web typecheck`。
- 项目检查：`node_modules/.bin/vp.cmd check`。
- `git diff --check`。

### 浏览器验证

使用隔离的 T3 Code 测试环境验证桌面宽度和窄屏：

- 常规页和外观页没有明显的应用自有中英文混排。
- 顶栏、面包屑、作用域菜单和不可用提示已汉化。
- 中文和英文查询都能导航到同一设置项。
- 菜单、弹窗、折叠区、主题操作和恢复默认值仍可操作。
- 没有新增文字裁切、水平溢出、控件下移或遮挡。

## 风险与控制

- 中文文本通常更长。通过保持布局代码不变并在桌面与窄屏检查截断和溢出来控制风险。
- 搜索字段增加后可能改变排序。通过保留英文静态字段、对双语标题取最高排名及锁定既有英文顺序测试来控制。
- 共享设置组件可能让排除范围内页面出现零散翻译。通过调用方传入翻译文案并保留英文默认值来限制影响。
- 动态数据可能被误翻译。通过只翻译模板、将动态值作为插值参数传递来控制。
- 大量词典键可能遗漏。通过 `MessageKey` 推导、`satisfies Record<MessageKey, string>` 和键集合测试在提交前阻止遗漏。

## 回滚边界

本轮不包含数据迁移、依赖升级或设置结构变更。回滚只需要撤销本轮设置汉化提交；已有语言偏好和基础汉化仍可独立保留。由于稳定设置值、路由和持久化格式不变，回滚不会要求清理用户数据。
