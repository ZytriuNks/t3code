# Web 简体中文汉化第二部分设计

## 目标

在 `feat/web-zh-cn-part-2` 分支上继续现有 Web i18n 体系，完成普通用户常用设置页与顶栏的大部分简体中文汉化，同时保持英文默认界面、设置行为、搜索目标和动态技术信息不变。

## 背景

现有实现已经提供：

- `en` 与 `zh-CN` 两种语言；
- 类型化消息键及中英文消息字典；
- `useI18n()` / `t(...)` 组件接入方式；
- 设置页框架、设置搜索、常规设置和外观主题的主要汉化；
- 中英文消息键一致性和设置搜索测试。

本轮继续复用这些机制，不引入新的翻译依赖、状态容器或自动翻译抽象。

## 范围

### 包含

1. 顶栏及其菜单：
   - 分支/引用选择器；
   - 环境选择器；
   - 工作区模式选择器；
   - 相关搜索、加载、复制、创建、切换、提示和错误文案。
2. 常规设置中新加入的“跟进消息行为”选项。
3. 普通用户设置页及嵌套界面：
   - 项目；
   - 连接；
   - 集成；
   - 源代码管理；
   - 提供商；
   - 快捷键；
   - 截屏；
   - 与上述页面直接关联的弹窗、Toast、菜单、Tooltip、占位符和无障碍标签。
4. 设置搜索中与上述页面对应的标题和关键词。
5. 选定范围内由本轮上游同步新引入的界面文案。

### 排除

- 诊断页；
- 资源监控和资源遥测页；
- 开源许可证/第三方声明页；
- 移动端界面；
- 桌面原生菜单；
- 设置存储、路由、搜索排序和业务逻辑变更；
- 与汉化无关的重构。

## 架构

`apps/web/src/i18n/messages.ts` 继续作为唯一消息源。英文与简体中文字典保持相同键集合，英文保持默认语言。

组件在最接近文案渲染的位置调用 `useI18n()`。设置行标题继续通过 `searchableSetting(id, t)` 复用设置搜索消息键，避免页面标题和搜索结果产生两套文案。

模块级静态选项若需要翻译，将转换为接收翻译函数的小型构造函数；不会在模块加载阶段读取当前语言。不会新增全局状态、Context、依赖或仅供本轮使用的通用抽象。

## 消息组织

消息键按界面归属分组：

- `toolbar.branch.*`
- `toolbar.environment.*`
- `toolbar.workspace.*`
- `settings.general.followUpBehavior.*`
- `settings.project.*`
- `settings.connections.*`
- `settings.integrations.*`
- `settings.sourceControl.*`
- `settings.providers.*`
- `settings.keybindings.*`
- `settings.snapshots.*`

已有语义相同的消息键必须复用，不创建同义重复键。组件中不直接写简体中文字符串。

## 文案数据流

- 静态文案：`t(key)`。
- 插值文案：`t(key, values)`，环境名、版本号、时间等作为值传入。
- 小型展示子组件优先接收已翻译的 `label`、`description` 或消息函数。
- 含大量独立文案的页面级或对话框级组件可以自行调用 `useI18n()`，避免扩大父组件接口。
- 设置搜索继续同时索引英文与当前语言的标题、分区名称和关键词，稳定 ID 与排序逻辑保持不变。

## 技术内容与错误策略

翻译界面外壳，保留下列动态技术值的原文：

- 命令及命令输出；
- 文件系统路径；
- Git 分支、标签和其他引用；
- 提供商、模型和产品名称；
- 后端返回的未知原始错误详情。

已知错误的标题、操作建议和状态标签需要汉化。若显示原始错误详情，应将它作为动态值附加在已翻译的界面文案中，不改写错误内容。

## 分批实现

### 批次 1：顶栏与新增常规选项

覆盖 `BranchToolbar*` 组件和“跟进消息行为”设置。该批次建立顶栏消息命名和测试模式。

### 批次 2：项目与连接

覆盖项目名称、图标、项目操作、环境连接、配对、WSL、Tailscale、授权客户端及相关弹窗和提示。

### 批次 3：集成与源代码管理

覆盖浏览器/设备集成、Cookie 导入、视口与录制选项、Git 获取、托管平台、写作风格和更改请求模板。

### 批次 4：提供商

覆盖提供商列表、实例管理、模型管理、运行时设置、安装/更新状态、变量和相关弹窗。

### 批次 5：快捷键与截屏

覆盖快捷键搜索、条件编辑、新建/删除操作，以及截屏配置、权限、声音、动画、设置向导和故障排查。

### 批次 6：残余英文审计

扫描上述已确认范围，修复遗漏的可见文案、Tooltip、Toast、占位符和无障碍标签。只保留明确允许的动态技术值和排除页面文案。

## 测试策略

每个批次采用测试先行：

1. 在现有测试文件中增加简体中文渲染、交互结果或消息断言；
2. 运行测试并确认它因缺少翻译接线而失败；
3. 添加最小消息键和组件接线；
4. 运行该页面测试、`apps/web/src/i18n/messages.test.ts` 和 `apps/web/src/components/settings/settingsSearch.test.ts`；
5. 该批次通过后形成独立提交。

优先扩展已有测试；只有现有测试无法覆盖目标组件时才新增测试文件。

## 最终验证

1. 运行所有本轮涉及的定向 Web 测试。
2. 运行 `@t3tools/web` 类型检查。
3. 运行 `vp check`，确认格式和 lint 无新增错误。
4. 使用隔离的 T3 Code Web 环境分别选择英文和简体中文，检查：
   - 设置导航和搜索；
   - 顶栏及其菜单；
   - 选项值、按钮、弹窗、Toast 和 Tooltip；
   - 语言切换后动态文案同步更新。
5. 执行残余英文扫描，对每个命中项确认它属于动态技术值、品牌名、排除页面或真实遗漏。

## 成功标准

- 已确认范围内不再出现未说明的硬编码英文用户界面文案。
- 英文界面文案和默认行为不发生语义变化。
- 中英文消息字典键集合一致。
- 设置搜索能使用英文和中文查询到同一稳定目标。
- 命令、路径、Git 引用、提供商/模型名和后端原始错误保持原样。
- 定向测试、Web 类型检查和 `vp check` 通过；已有无关警告单独报告，不作为本轮修改内容。
- 每个批次可独立审查和回滚，不覆盖现有 PR 或其他工作树中的未提交改动。
